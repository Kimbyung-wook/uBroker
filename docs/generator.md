# Code Generator

English | [한국어](generator_kr.md)

`code_gen/ubroker_gen.py` reads `.msg` files and writes C code. It needs Python 3.6 or later and uses only the standard library.

## Usage

```
python code_gen/ubroker_gen.py -i <msg dir> -o <output dir> [--lang en|ko]
```

| Option | Description |
|---|---|
| `-i`, `--input` | Folder with `.msg` files (required) |
| `-o`, `--output` | Folder for generated files (created if missing, required) |
| `--lang en\|ko` | Language of error messages and `--help` (default `en`). Generated code comments are always English |

Exit code: `0` on success, `1` on any error.

## Outputs

| File | Contents |
|---|---|
| `<msg>.h` | Struct `<msg>_t`, constants, `<MSG>_INITIALIZER` |
| `ubk_msgs.h` | Includes all message headers, topic IDs `ubk_topic_id_t`, declaration of the topic info table |
| `ubk_msgs.c` | Message defaults, topic shared memory, topic info table `g_ubk_topic_meta[]` |

The files in `core/` (`ubk_types.h`, `ubroker.h`, `ubroker.c`) are not generated. Add them to your build as they are.

Build setup:
- include paths: `core/`, the output folder
- sources: `core/ubroker.c`, `<output>/ubk_msgs.c`

Every generated file starts with a one-line notice:

```c
/* Auto-generated by ubroker_gen.py from weapon_state.msg. DO NOT EDIT. */
```

Do not edit generated files. Change the `.msg` file and generate again.

## Incremental Generation

- A file is rewritten only if its content changed. Each file is reported as `updated` or `unchanged`, so the build system recompiles only what changed.
- Adding or removing a topic changes `ubk_msgs.h` (topic IDs), so sources including it are recompiled.
- When a `.msg` file is deleted, its generated header is removed (`removed`). Only `.h`/`.c` files that start with the generator notice are deleted, so your own files in the output folder are safe.

```
  unchanged sensor_imu.h
  updated   weapon_state.h
  updated   ubk_msgs.h
  unchanged ubk_msgs.c
  removed   old_msg.h
```

## Checks

All files are checked before anything is written. If there is any error, no file is written or deleted.

- Syntax errors, messages without fields
- Unknown types, circular nested messages
- Default value format and range, array default count
- Bitfield type, width and fill
- Name rules: snake_case, first letter, 31-character limit, C keywords, `ubk_` prefix, reserved names, duplicates
- Duplicate topic names, `TYPE_ONLY` used together with `TOPICS`

Example:

```
msg/weapon_state.msg:8: error: bit width must be 1 ~ 8
msg/sensor_imu.msg:9: error: bitfield group (is_calibrated~) does not fill its uint8 storage unit (7/8 bits used). Declare the remaining bits as a reserved field
2 error(s). Nothing was generated.
```

See [`msg_syntax.md`](msg_syntax.md) for the rules themselves.
